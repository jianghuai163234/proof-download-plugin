# 校样下载插件（本地测试版）

这是飞书多维表格侧边栏插件，不是 Excel 插件，也不是浏览器扩展。已完成公开网页部署、自动测试和演示下载，尚未完成真实飞书验收。

正式服务地址：https://jianghuai163234.github.io/proof-download-plugin/
飞书插件名称：校样下载插件。正式服务地址不要加 ?demo=1；普通浏览器预览可加 ?demo=1。

## 先看效果

当前电脑开发服务运行期间，打开 http://127.0.0.1:5173/?demo=1 。演示使用虚拟店铺和 SVG 图片，不连接飞书。

演示操作：选择买家姓名 → 只读查看下载清单 → 展开其他店铺添加 Judy → 一键下载。可以得到两家店铺共 6 个示例图片及一份下载清单。

## 以后如何安装到飞书

1. 将 dist/ 内的全部文件部署到你选择的静态 HTTPS 托管服务（保留 assets/ 目录）。已发布至 GitHub Pages，但尚未修改飞书插件配置。
2. 在飞书“自定义插件 → 新增插件”中，名称填“校样下载插件”，服务地址填实际部署后的 HTTPS 地址，**不添加 ?demo=1**。
3. 添加插件可能受管理员/租户权限限制，入口是否对团队可见以飞书实际设置为准。不要为了测试修改团队记录或现有权限。
4. 打开店铺的订单表格视图，再从侧边栏打开插件；仪表盘没有当前订单视图，插件会提示先打开表格。
5. 先点击“只读查看下载清单”，与筛选后表格数量及上下顺序核对，再点击一键下载。

本机测试服务也可尝试 http://127.0.0.1:8765/ ，但是否允许 HTTP/本地地址由飞书和浏览器策略决定；如果被阻止，应改用合规的 HTTPS 托管，不绕过浏览器保护。此地址仅属于当前电脑；同事电脑的 127.0.0.1 指向他自己的电脑，不能用你的本机服务。

## 使用规则

- 新收到校样视图默认选择“校样1”；修改视图默认选择“最新校样”。未知视图不会猜测，需手动选附件列。
- 记录读取始终带 viewId，不另传筛选或排序，不退回整表；分页单页 200，继续读取后续页。
- 沿用接口返回的视图记录顺序。记录在读取期间改变会中止；接口不是事务快照，无法保证多人同时编辑时每个单元格的同一时刻快照。
- 有附件的记录按顺序编号；空附件跳过，同格多附件按数组顺序依次编号。下载失败的序号不重排。
- image 模式：image1.jpg、image2.jpg；买家姓名：1_姓名.jpg、2_姓名.jpg。姓名称为空用“未填买家姓名”。支持选择姓名文本列。
- 单店铺：压缩包为“店铺名称.zip”。只选一个视图时，图片直接在 ZIP 根目录；多个视图时按“新收到校样”“修改”等视图名分文件夹，各视图独立编号。
- 多店铺：外层为“校样下载.zip”，内部每店一个“店铺名称.zip”；各店包内仍沿用单视图直接放图、多视图分文件夹的规则，需要解压两层；没有附件的店铺跳过，不生成空店铺ZIP。
- 发生分包时，单店铺命名为“店铺名称_1.zip”“店铺名称_2.zip”；多店铺为“校样下载_1.zip”“校样下载_2.zip”。各分包只包含该批有结果的店铺，须保留全部分包；图片原计划编号不重排。重名店铺/视图加_2等后缀避免覆盖。
- ZIP 不再生成下载清单 TXT；失败项仅在当前插件面板显示，包含店铺、视图和计划文件名，不包含临时链接或附件 token。
- 下载命名偏好只保存在本机浏览器；额外店铺任务列表属于本次打开会话，关闭插件后需重新添加。
- 单文件最多 64 MiB；每包不限制附件数量，附件原始大小合计最多 500 MiB，超过分包。限制的是附件字节量，不是严格内存峰值；ZIP 与缓冲复制会增加额外内存。
- 记录读取每组最多 4 行并发，图片每组最多 2 张并发；每组完成后按原清单顺序写入ZIP，不按请求完成顺序编号。每个附件重新取临时URL，失败最多尝试2次，单次网络超时60秒。
- 大批量分包可能被浏览器阻止自动连续下载。界面只报告已发起下载，不声称磁盘写入成功；需要检查浏览器下载列表及插件面板中的失败项。
- 取消停止后续处理，已经发起的 ZIP 不能撤回；已读但未打包的本批附件将丢弃。

## 只读与数据流

业务代码只使用官方 SDK 的 get*/onSelectionChange 接口，没有 set/add/delete/update/applySetting 表格操作。
数据在当前使用者的浏览器内处理。只通过飞书 SDK 读取权限内信息，并访问飞书返回的 HTTPS 附件链接。没有自建数据接收后端、分析追踪或上传功能。
临时附件链接和 token 不写进错误面板或控制台。ZIP只包含附件（多店铺时内含各店铺ZIP），不生成TXT清单；买家姓名模式的文件名属于业务信息，请妥善保存。

## 真实飞书验收（尚未完成）

- 当前店铺和视图能自动识别，切换后立即跟随。
- 有筛选的表格返回记录数与画面一致；200 条以上无漏读。
- 尤其核对“重画 → 修改”的分组顺序、手动拖动排序、折叠组的记录语义，不把示例测试当作验证通过。
- 未打开的其他视图能读取其生效筛选；个人临时筛选是否一致需实测。
- 校样字段及买家姓名正确；同格多图与空附件正确。
- SDK 附件链接权限、CORS、iframe 下载限制和实际原图字节正确。
- 下载前后表格值及勾选状态不变；插件安装本身是否对团队共享需核对。

## 本次文件清单

- package.json、package-lock.json：依赖与命令。

- src/core.ts：文件名、顺序清单、分页。
- src/reader.ts：限定视图的只读读取及变更检测。
- src/concurrency.ts：按分组限制并发并保留输入顺序。
- src/feishu.ts：官方 SDK 适配及下载 URL 获取。
- src/download.ts：限量下载、取消、ZIP 与失败清单。
- src/main.ts、src/style.css：交互面板及样式。
- src/demo.ts：独立虚拟数据演示。
- tests/core.test.ts、tests/workflow.test.ts、tests/archive.test.ts、tests/performance.test.ts：行为、压缩结构及并发顺序测试。
- 启动本地测试.cmd、README.md：测试入口和使用说明。
- dist/：生产构建产物，包含要托管的静态页面。

## GitHub Pages 发布

此项目目录应作为独立公开仓库的根目录上传，不要上传上一级 skill 工作区。

1. 在你的 GitHub 账号中创建专用公开仓库，将本目录源码（含隐藏的 .github/）提交到 main 分支；不要提交 node_modules、dist、本地 ZIP、下载报告、账号凭据。
2. 进入仓库 Settings → Pages，将 Build and deployment / Source 设为 GitHub Actions。
3. 在 Actions 中运行“校样下载插件发布”，或向 main 提交代码触发；测试和构建成功后会发布 dist/。
4. 只有 GitHub 返回实际部署网址且网页可以访问后，才把它填到飞书的服务地址。未运行部署前，不把推测网址当作已经可用。
5. 正式地址不加 ?demo=1；加 ?demo=1 仅用于虚拟数据演示。

工作流仅对 main 推送或手动触发执行部署；PR 只运行检查，不发布。contents 默认只读，Pages 写权限只授予部署任务。代码公开不代表飞书表格公开，插件仍在当前使用者权限内读取附件。
